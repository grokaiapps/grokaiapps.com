Agentic payments guide

Stand up a dual-rail desk: Stripe packs for people, USDC on Base via x402 + CDP for agents. Working example: desk.grokaiapps.com.

Two rails, one desk

RailWhoHow
Human People with cards Stripe Checkout packs on the desk → cookie credits → run jobs
Agent Machines with wallets Discover → unpaid POST → HTTP 402 → settle USDC → retry

Do not force agents through card Checkout. Do not force people through on-chain USDC.

People path (summary)

  1. Price for the $0.50 floor. Card Checkout needs totals ≥ $0.50. Sell packs, not lone $0.03 charges.
  2. Expose packs. GET /v1/packs — stable pack ids, credit counts, prices.
  3. Create Checkout server-side. POST /v1/checkout/session → hosted Checkout URL. Never put secret keys in the browser.
  4. Credit on webhook. Verify checkout.session.completed with STRIPE_WEBHOOK_SECRET.
  5. Keep leftovers in Stripe. Ephemeral disk dies on redeploy. Prepaid counts must survive.
  6. Humans run on the desk. After Checkout, desk.grokaiapps.com sets a private credits cookie — no key to paste. (Agents/scripts may still use X-Entitlement-Key.)

Agent path (summary)

  1. Publish free discovery. Catalog, network, pay-to. Desk uses /v1/discovery, /v1/catalog, /.well-known/x402.
  2. Return HTTP 402 when unpaid. Include PAYMENT-REQUIRED (amount, Base / eip155:8453, pay-to).
  3. Settle via CDP when live. Verify with CDP keys. Stub settlement is for local smoke only.
  4. Retry with payment proof. Same job POST, plus payment headers.
  5. Keep free paths free. Discovery, health, job status reads.

Honest gotchas

  1. Checkout $0.50 floor. Packs are the product design.
  2. Shared-hosting bot / captcha. Agent and webhook traffic can get blocked. Prefer a container host (e.g. Render) for the live API.
  3. Leftovers must not live only on ephemeral disk. Persist via Stripe or another durable store.
  4. Stub settlement ≠ live money. Production must verify.
  5. Webhook authenticity. Enforce STRIPE_WEBHOOK_SECRET.
  6. Rate limits. Per-IP and per-entitlement on paid routes.

Human flow

1. Open https://desk.grokaiapps.com (hire UI)
2. POST /v1/checkout/session  {"pack_id":"pack_url_probe_17"}  # or Buy on UI
3. Human completes Checkout URL
4. Webhook credits entitlement; /checkout/success sets HttpOnly cookie
5. Browser runs jobs with cookie (no paste)
   Scripts may send: X-Entitlement-Key: buyer@example.com

Agent flow

1. GET  /v1/discovery          # free — SKUs, network, payTo
2. POST /v1/jobs/url-probe     # unpaid → HTTP 402 + PAYMENT-REQUIRED
3. Client pays USDC on Base (x402)
4. POST same job + payment proof headers
5. Job runs; return result

Suggested build order

1. Job handlers + local bypass (dev only)
2. Free discovery/catalog JSON
3. x402 middleware: 402 + PAYMENT-REQUIRED → CDP verify
4. Stripe packs + Checkout session + signed webhook
5. Durable leftover storage (Stripe-backed)
6. Deploy API where agents are not captcha'd
7. Static marketing site
